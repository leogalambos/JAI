## Canonical agents

| Agent | Model class | Purpose |
| --- | --- | --- |
| `architecture-repository-engineer` | `standard` | Operates the 26.10.4 EA-domain projection repository, imports/exports Open Exchange files, generates governed views, preserves stable identifiers and defers global semantic identity to JAI. |
| `artefact-governor` | `standard` | Assesses and designs the governance of a software product or document library: ownership, review cycles, versioning and release practice, change approval trail, changelog, CODEOWNERS, retention and the policy that holds it together. Produces a governance assessment with located findings and a proposed governance model. Use for 'who owns this', 'is our documentation governed', 'set up change control for this repository', or governance audits. Reads git history and files; never changes them. |
| `authority-liaison` | `light` | Prepares an escalation packet for the human authority in layered justifiable delivery: the conflict, the chain of layers it passed through, the options, the evidence each rests on, and the exact fabric.py command the human must run. Never decides and cannot record an authority act. Use when an escalation has relayed to Layer 1 or a product awaits authority acceptance. |
| `codebase-reviewer` | `standard` | Performs a deep review of an existing codebase and reports prioritised findings: architecture conformance, coupling and change hotspots, test coverage against risk, dependency and supply-chain exposure, security patterns, operability gaps. Use for inherited systems, technical due diligence, pre-rewrite assessment, recurring-defect investigation, or any request to \"review this repository\", \"audit our code\" or \"tell us what to fix first\". Reads and measures only; never edits the code. |
| `defect-analyst` | `heavy` | Analyses a defect to its root cause before anyone fixes it: reproduces it as a command, measures whether it is intermittent, then compares against the last known good state (bisecting in a separate worktree), against a working analogue (the same code elsewhere, a sibling function, another input or environment) and against timing (timeouts, async completion, ordering, clocks, schedules, expiry). Tests competing hypotheses and returns a validated analysis. Use for 'why does this fail', 'it worked last week', 'it fails sometimes', 'works here but not there'. Diagnoses and verifies; never fixes. |
| `docs-author` | `standard` | Writes and edits standalone documentation: guides, references, tutorials, articles, books, website and wiki content. Writes into the documentation tree only (docs/, site/, content/, *.md, *.mdx, *.rst, *.adoc) and never into source files. Use for Technical Writer, Content Designer, Developer Advocate and Knowledge Manager work. In-source comments such as JavaDoc or docstrings are not this agent's. |
| `document-reviewer` | `standard` | Analyses and reviews a document library — books, articles, guides, policies, wikis, websites as source — for accuracy, consistency, structure, terminology, cross-references, ownership and currency. Records located findings in a findings ledger and verifies rework by others. Use for 'review our docs', 'audit this policy set', 'is this documentation still right', or before publishing. Reads and measures only; never edits the documents. |
| `engagement-authorisation-guard` | `standard` | Mandatory gate before any offensive-security role skill is used. Verifies that written authorisation, signed scope, rules of engagement, testing window, emergency stop procedure and named contacts exist and are current. Use for penetration testing, red teaming, social engineering, physical intrusion, adversary emulation and vulnerability research requests. Blocks the work if authorisation is absent or ambiguous. |
| `enterprise-publication-editor` | `standard` | Transforms an approved semantic artefact into an audience-appropriate enterprise publication while preserving claims, decisions and traceability. |
| `evidence-rationale-reviewer` | `standard` | Reviews material claims, decisions, assumptions, alternatives, evidence strength and residual risk before publication. Never changes the underlying decision. |
| `experiment-engineer` | `standard` | Runs research and development experiments: writes a pre-registered plan with hypothesis and success criteria before anything runs, builds a deliberately disposable prototype or benchmark in an experiments/ workspace, executes it reproducibly, and records results including negative ones. Use for proof-of-concept, benchmark, spike or feasibility work in R&D. Prototypes never leave the experiments folder as production code. |
| `fabric-auditor` | `light` | Independently audits a traceability fabric produced by layered justifiable delivery. Verifies the hash chain, authority signatures, well-typedness, adjacency, forward acyclicity and evidence-file integrity, and reports which fragments are justifiable under the published definition and under strict mode, with the rule that fired for each failure. Use before any fragment is treated as an authorised product, and whenever someone asks why the system is entitled to use an output. |
| `gate-auditor` | `standard` | Verifies that a deliverable satisfies the output gates of the role skill that produced it, using the bundled check_gates.py script. Use before releasing any consequential deliverable, and whenever a gate check has been asserted rather than demonstrated. Reports pass, fail or waiver problems; never fixes the deliverable itself. |
| `l1-intent` | `heavy` | Layer 1 (Intent and Context) agent for layered justifiable engagements. Establishes why the work exists, for whom, the success criteria, risk boundary and authority; issues the contract to Layer 2; reviews Layer 2 fragments; and answers the engagement's requirement upward to the human authority. Use only when the layered-justifiable-delivery skill dispatches this layer, never for a single-step task. |
| `l2-meaning` | `standard` | Layer 2 (Meaning and Domain Model) agent for layered justifiable engagements. Interprets the intent contract into concepts, scope, terminology and domain rules; derives contracts for Layer 3; reviews Layer 3 fragments. Use only when the layered-justifiable-delivery skill dispatches this layer. |
| `l3-policy` | `heavy` | Layer 3 (Reasoning, Policy and Control) agent for layered justifiable engagements. Applies policies, controls, constraints, risk logic and acceptance criteria; derives design contracts for Layer 4; reviews Layer 4 fragments. Cannot delete a requirement: an infeasible control becomes a derived requirement for a compensating control plus a conflict. Use only when the layered-justifiable-delivery skill dispatches this layer. |
| `l4-design` | `standard` | Layer 4 (Solution Design) agent for layered justifiable engagements. Transforms rules and constraints into process, technical, analytical or architectural design; derives realisation contracts for Layer 5; reviews Layer 5 fragments. Returns a conflict when no feasible design satisfies the contract. Use only when the layered-justifiable-delivery skill dispatches this layer. |
| `l5-realisation` | `heavy` | Layer 5 (Realisation and Tooling) agent for layered justifiable engagements. Builds or configures the concrete artefacts a design calls for: code, infrastructure as code, pipeline definitions, container builds, prompts, configuration. The only layer agent that writes, and it writes only in the workspace. Derives evidence contracts for Layer 6 and reviews Layer 6 fragments. Use only when the layered-justifiable-delivery skill dispatches this layer. |
| `l6-evidence` | `standard` | Layer 6 (Execution and Evidence) agent for layered justifiable engagements. Executes deterministic checks and collects evidence: tests, scans, plans, queries, logs, configuration exports. Holds Bash but no Write or Edit: it has no file-editing tool, and the hooks and its instructions cover the shell. Returns observations with files the runtime hashes; never conclusions or recommendations. Use only when the layered-justifiable-delivery skill dispatches this layer. |
| `library-approver` | `standard` | Reviews a staged change to the IS/IT role library and approves or rejects it. Holds no Write or Edit, so it cannot alter the proposal it is judging. Use after library-author stages a change and before library-release applies it. Checks Agent Skills compliance, the tier model, the blast radius and the reversal path, then records a decision. |
| `library-author` | `standard` | Drafts changes to the IS/IT role library: new or edited roles, archetypes, agents and generator code. Writes only into it-role-library/staging/, never into the live skills/ or agents/ directories. Use for any proposed change to the library itself. Produces the staged change, a blast-radius statement and a validator run against the staged tree, for library-approver to review. |
| `library-release` | `standard` | Applies an approved staged change to the live IS/IT role library, mechanically. Use only after library-approver has approved and a human has recorded the approval. Rebuilds from the generator, re-runs the validator, updates the changelog, and reports what moved. Exercises no judgement about whether the change was a good idea. |
| `model-consistency-reviewer` | `standard` | Independently reviews the 26.10 enterprise architecture repository for broken references, orphaned elements, cross-project ownership gaps, lifecycle conflicts, view drift and decommission blockers. |
| `research-analyst` | `research` | Researches a problem: frames the question and the decision it informs, surveys prior art and current practice from primary sources, grades source reliability, lays out competing hypotheses and the evidence for each, and recommends adopt, trial, assess or hold. Also assesses experiment results against their pre-registered criteria. Use for 'research how to…', 'what is the state of the art in…', 'evaluate options for…', or the research phase of R&D. Reads and cites; never builds. |
| `role-advisor` | `standard` | Operates advise-tier role skills: executive, governance, assurance, audit, risk, compliance, privacy and offensive-security roles. Use when the selected role's skill declares allowed-tools of Read, Grep, Glob, WebSearch. Produces analysis, assessments, findings, option sets and recommendations in the response, never as changes to a system. |
| `role-author` | `standard` | Operates author-tier role skills: analysis, architecture, design, practice management and enablement roles. Use when the selected role's skill declares allowed-tools including Write and Edit but not Bash. Produces specifications, architectures, plans, models, designs and documentation as files. |
| `role-engineer` | `standard` | Operates execute-tier role skills: software engineering, infrastructure, cloud, operations, testing and research roles. Use when the selected role's skill declares allowed-tools including Bash. Implements changes, runs builds and tests, and produces operational evidence. |
| `role-router` | `light` | Selects which IS/IT role skill applies to a request and returns the routing decision with its reasoning. Use this first, before any role work begins, whenever a request could be handled by more than one role, names no role at all, or spans a boundary between two. Also use it to answer "who owns this?" questions about an IT operating model. |
| `sabsa-architect` | `research` | Prepares, creates and updates a SABSA security architecture library: business drivers, measurable business attributes, risks and opportunities, control objectives, domains and trust, logical services, physical mechanisms, components and the service-management operations that measure them — every element traced upward to the business. Use for building a SABSA library from scratch, extending it, or updating it after a change in the business or the estate. Writes library entries; never reviews its own work. |
| `sabsa-reviewer` | `standard` | Reviews a SABSA security architecture library and suggests improvements: runs the structural checks (traceability to business drivers, measurability of attributes, link integrity, matrix coverage), then judges whether each element is right and not merely present. Records located findings in a findings ledger, verifies rework, and produces ranked suggestions. Use for 'review our SABSA architecture', 'what is missing', 'is this traceable', or before a library version is approved. |
| `sod-reviewer` | `standard` | Reviews a proposed set of role assignments for segregation-of-duties conflicts, using section 13 of each role skill. Use when designing a team, writing a RACI, combining roles in a small organisation, assigning someone a second hat, or investigating why a control keeps failing. Produces conflict findings and compensating-control recommendations. |
| `source-docs-engineer` | `standard` | Adds or corrects documentation inside source files: JavaDoc, Python docstrings, XML doc comments, OpenAPI and schema annotations, README files inside modules. Use when documentation must live in the code rather than in a documentation tree. Treats every edit as a code change subject to review, build and the change path, because it is one. |
| `visual-quality-reviewer` | `standard` | Reviews rendered DOCX/PPTX/XLSX/HTML/SVG outputs for density, hierarchy, legibility, table/diagram usability, document control and presentation defects. |
