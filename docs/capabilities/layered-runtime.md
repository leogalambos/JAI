# Layered runtime and assurance

JAI's layered runtime coordinates consequential work through six content
perspectives, local independent review and exact versioned handoffs. It is one
of [three ways to use JAI](../using/usage-modes.md), alongside direct specialist
work and enterprise workflows.

## Content and process

Contextual, conceptual, logical, physical, component and management perspectives
each address What, Why, How, Who, Where and When. Management concerns also inform
the other perspectives. The [layer model](../architecture/sabsa-layer-model.md)
defines ownership; it does not require six separate documents for every product.

A local setter formulates the question, an author proposes a candidate and an
independent reviewer judges it. Each entity selects suitable specialties from
the full catalogue. Cross-question integration and receiving handoff acceptance
remain separate obligations.

## Current justification

Inputs and results have immutable version identities. Explicit decisions govern
which records currently apply to an output and cancel obsolete uses and their
dependent permissions. Historical records remain available without granting
permission to rely on them for changed inputs.

Continuing work does not accept its result. Acceptance and release assess the
specific output against its relevant current evidence and required decisions.
See the [versioned lifecycle](../architecture/governed-runtime-cutover.md).

## Native execution and bounded progress

The active Claude Code or Codex parent delegates task-specific contexts and
captures actual returns through the shared runtime. Work can pause and resume
at durable boundaries without repeating completed professional calls. Local
iteration limits and escalation prevent a stalled question from consuming an
unbounded allowance; they are not a mandatory deadline for the whole task.

An escalated layer pauses by default because shared assumptions may change.
The operator can explicitly permit bounded speculative continuation, without
accepting the resulting work. See [escalation and local limits](../architecture/governed-escalation-scheduling.md).

## Operator versus runtime

Users describe the outcome, inputs, constraints and reserved decisions through
the provider prompt. JAI prepares the exact runtime handoffs; users do not
construct worker packets or bootstrap JSON.

The runtime records work and checks relevant prerequisites. The host sandbox
enforces actual filesystem and tool permissions. JAI does not embed Prolog,
guarantee arbitrary professional truth or replace human accountability.

Only explicit reserved L0 decisions use the external human signing procedure.
Ordinary work records are unsigned. Follow the [operating guide](../using/layered-engagement.md)
and [human authority instructions](../operations/human-authority.md).
