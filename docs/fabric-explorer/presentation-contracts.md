# Read-only presentation state

The desktop interface uses an application-owned `ExploreController` over the fixed `DesktopBridge`. The controller has no DOM, filesystem, journal replay, source writer or authority operation. React observes `subscribe` and `getSnapshot`: the snapshot object remains stable until a transition publishes a new immutable state.

The state contains the accepted shell metadata, binding, active request lanes, finite search and findings pages, exact indexed counts/groups, bounded graph projection and numeric layout handles, inspector selection, original source page and history navigation availability. Inspector attributes retain the complete tagged semantic value or explicit paged descriptor. Long labels remain complete in state and the inspector.

`setShell` initializes an overview automatically when session, capability or accepted generation changes. A failed refresh that retains its generation updates the diagnostic/stale metadata and preserves the graph, selection and original source page. Generation changes invalidate pending presentation work and discard generation-specific history. Late results cannot replace the current view.

`loadOverview` loads search, findings, counts and groups, then a small neighbourhood seeded by the first matching identity. The initial neighbourhood is limited to 100 vertices, 300 edges and one hop. Normal exploration uses explicit work/visible limits; hidden counts are global snapshot counts minus the returned bounded graph. A path result distinguishes a found path, proved absence in the selected relation scope and an inconclusive bounded search.

Search and findings show at most 50 records per page. Requesting the next page replaces the current page rather than accumulating every previously viewed DTO. Remaining counts and terminal completeness come from the accepted index. Finding searches have their own authenticated cursor domain; ordinary search cursors cannot be reused there. Literal query text and the existing public query key remain unchanged.

Graph filters are evaluated by the accepted worker against the full indexed graph. This includes exact version-family resolution for use points whose version vertex is outside the displayed projection. The renderer receives bounded membership masks and applies them to its existing immutable records; it does not infer membership. A retained unfiltered projection makes filters reversible without another import. Filtered layouts use their own retained numeric projection. Mask length, canonical encoding, unused padding, endpoint closure, handle alignment, inherited omissions/completeness and global hidden counts are checked before publication. A rejected filter preserves the previous view and selector state.

Selection uses full canonical keys and identities. Relation inspection preserves the original direction, endpoints, attributes and source evidence. Finding-subject candidates come only from indexed `finding-subject` or `location-association` relations. Missing, unresolved, bounded or ambiguous candidates remain explicit rather than being guessed from text.

Source pages retain exact archived bytes and decimal byte offsets. The display-only UTF-8 decoding may show replacement characters when a page splits a multibyte character. Character counts never determine subsequent byte offsets. The default page request is 4096 bytes; the maximum is 256 KiB. Paged attributes use their explicit source locator; otherwise paging uses the selected record's locator.

History retains at most 50 detached navigation intents: graph-query context, exact selection address, filter, search text/order, findings text and grouping axis. It stores no DTOs, search cursors or projection tokens. Back/forward restores the intent in the current generation, reusing unchanged current projections/pages and re-executing changed bounded queries. Changed search queries restart at their first bounded page; page-advance actions do not add history entries. A relation's original bounded query context permits exact inspector restoration even after navigating to a different visible graph. A fresh action truncates forward history and supersedes unfinished history reconstruction. Same-generation failed refresh preserves history; a new generation clears it. Cancellation targets only owned requests and keeps the accepted worker and source snapshot. Replacement, stale results and disposal release tokens with their original request owner. Errors expose fixed application-authored explanations, never arbitrary native exception text.

Controller methods are `setShell`, `loadOverview`, `search`, `findings`, `select`, `selectElement`, `neighbours`, `path`, `setFilter`, `setGroupAxis`, `pageSource`, `back`, `forward`, `cancel` and `dispose`. All actions return promises; subscribers see immutable publications throughout their lifecycle.
