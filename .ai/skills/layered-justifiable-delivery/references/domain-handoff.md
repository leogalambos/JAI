# Native Gen2 handoff from a professional workflow

Ordinary bounded analysis, criteria lookup, research, development, diagnosis,
repository maintenance and domain calculations keep their existing workflows.
Use this handoff when the requested use requires governed layered justification,
or when the user explicitly requests it. Do not force unrelated routine work
through six layers or label a consequential result ordinary to bypass its gates.

1. Preserve the actual request, intended output/use, scope and immutable input
   references. Keep the exact selected criteria, authored candidate, evidence,
   findings, assumptions and unresolved questions as applicable. Prior standalone
   work is attributable input, not retroactive Gen2 verification or acceptance.
2. Invoke the canonical `layered-justifiable-delivery` skill through the active
   provider's existing native mechanism. The user-facing entry is `/layered` in
   Claude and `$workflow-layered` in Codex. The parent captures the actual task
   and handles `governed_layered.py` transport internally. Never require the user
   to author bootstrap JSON, implement a worker or start another model client.
3. If this is continuation, name the existing engagement and its exact current
   references. Resume its unfinished work and preserve bounds; do not replace it
   silently. Changed inputs require their existing owner-directed version/change
   route, not direct edits to accepted records or historical PASS inheritance.
4. Incoming work addresses the receiving layer's outcome and interface. That
   layer formulates its questions and chooses professionals, models and method
   from the complete intrinsic catalogue. A neighbour does not hire its author
   or reviewer. Keep author and reviewer contexts independent; pass required
   inputs and candidate evidence, not another entity's conversation.
5. Keep prompts compact. Supply the actual mandate and mandatory constraints;
   reference larger exact documents and let the entity read/request relevant
   sections across questions. Do not silently truncate obligations, assume a
   fixed same-question dependency, or confuse selected context with an access ACL.
6. Let the existing Store and native bridge admit actual results and select
   current scoped justification. Review, human acceptance and release are
   separate facts. Only L0 signs reserved decisions through the external
   companion. Neither the domain workflow nor this handoff grants authority.

For commercial/content/publication integration the trusted parent supplies the
existing callbacks through `governed_domain.GovernedDomain`, pinned to exact
producer UsePoints outside immutable material. Producer/reviewer provenance tokens
use the pre-issued context and stable logical ID before authorship; echoed names
or tokens alone are not execution evidence. Actual material, captured returns,
scoped selected review and current permissions remain required. Do not synthesize
content-unit PASS from an aggregate qualified flag, rewrite authored material to
insert its own version hash, or recreate ordinary-producer signing.

The independent audit entry `/fabric-report` / `$workflow-fabric-report` explains
the recorded basis and gaps without changing it. Report missing native tools,
material or authority precisely and preserve the original work. Source restoration
does not establish installed activation or an unobserved live-provider run.
